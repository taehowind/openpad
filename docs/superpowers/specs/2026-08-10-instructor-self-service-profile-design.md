# 강사·관리자 본인 계정 수정

강사와 관리자가 대시보드에서 자기 이름을 눌러 **이름과 비밀번호**를 직접 바꾼다. 이메일은 바꿀 수
없다. 지금은 어느 화면에도 이 기능이 없어, 비밀번호를 바꾸려면 DB를 직접 건드려야 한다.

## 배경 — 강사 이름이 저장되는 방식

개명 시 무엇을 함께 고쳐야 하는지는 이름이 어디에 복사되어 있느냐로 결정된다. 두 경우가 있고,
둘의 성격이 다르다.

| 작성 경로 | `author_name` 에 들어가는 값 | 개명의 영향 |
|---|---|---|
| 본인이 관리하는 보드에 강사로 작성 | 리터럴 `"강사"` (`access.ts` 의 `actorForBoard`) | 없음 — 실명이 아예 저장되지 않음 |
| 회원 전용 보드에 멤버로 작성 | 등록 시점의 실명 (`participants.nickname` 복사) | 있음 — 이쪽이 유일한 대상 |

두 번째 경우의 참가자 행은 `participants.device_id = 'ins:<instructorId>'` 로 정확히 식별된다
(`ensureMemberParticipant`). 강사를 가리키는 외래키는 없지만 이 관례가 사실상 그 역할을 한다.

## 갱신 범위

이름이 바뀌면 한 트랜잭션 안에서:

- `participants.nickname` — `device_id = 'ins:<id>'` 인 모든 행
- 그 참가자가 작성한 `cards` / `comments` / `chat_messages` 의 `author_name`

건드리지 않는 것:

- `audit_logs.actor_name` — "그 시점에 누가 무엇을 했다"는 기록이다. 사후에 고치면 기록으로서
  의미가 없어진다.
- `board_revisions.state_json` — 스냅샷이므로 같은 이유로 보존한다.
- `presence.nickname` — 하트비트가 30초 안에 덮어쓴다.

## API

`PATCH /api/instructors/me` (신설)

```
{ name?: string, currentPassword?: string, newPassword?: string }
```

- 활성 강사 세션이면 누구나 호출 가능. 역할 무관, 대상은 항상 본인.
- `name` 만, `newPassword` 만, 또는 둘 다 허용. 셋 다 없으면 400.
- `newPassword` 가 있으면 `currentPassword` 필수이며 `verifyPassword` 로 검증. 불일치 시 403.
- `name` 은 trim 후 1–60자, `newPassword` 는 8자 이상.
- 분당 10회 `rateLimited`. 인증된 세션이어도 현재 비밀번호를 맞히려는 시도를 막는다.

기존 `/api/instructors/[id]` 는 관리자 전용이고 `role`·`status` 를 다룬다. 본인 수정을 거기에
섞으면 "관리자만"과 "본인만"이라는 서로 다른 두 규칙이 한 핸들러에 공존하게 되므로 분리한다.

세션 쿠키는 재발급하지 않는다. `getInstructorSession()` 이 매 호출마다 DB 행을 다시 읽으므로
이름 변경이 즉시 반영된다.

## UI

`AdminClient` 헤더의 `account-chip`(현재 `<span>`)을 버튼으로 바꾸고 모달을 연다. 기존
`.modal-backdrop` / `.modal-card` 패턴을 그대로 쓴다.

- 이메일: 읽기 전용 텍스트. 수정 대상은 아니지만 어느 계정인지 보여준다.
- 이름
- 현재 비밀번호 / 새 비밀번호 / 새 비밀번호 확인 — 비우면 비밀번호를 바꾸지 않는다.
- 새 비밀번호와 확인이 다르면 제출 전에 클라이언트에서 막는다.

성공하면 모달을 닫고 대시보드의 계정 정보를 새로 읽는다.

## 범위 밖

- **비밀번호를 바꿔도 다른 기기의 세션은 끊기지 않는다.** JWT 에 버전이나 jti 가 없어 무효화할
  수단이 없다. 기기를 분실한 상황에서는 비밀번호 변경만으로 부족하다는 뜻이며, 세션 무효화는
  별도 작업으로 다룬다.
- 강사 작성 카드가 실명 대신 `"강사"` 로 보이는 동작 자체는 바꾸지 않는다.
- 관리자가 다른 회원의 이름·비밀번호를 대신 바꾸는 기능은 넣지 않는다.
- 보드 화면(`/board/[id]`)에는 본인 이름 표시가 없어 진입점을 두지 않는다.

## 검증

테스트 러너가 없으므로 `npm run build`, `npm run lint` 와 실제 앱 확인으로 검증한다. 하네스에
추가할 항목: 이름 변경이 세션과 회원 목록에 반영되는지, 틀린 현재 비밀번호가 403 인지, 바뀐
비밀번호로 로그인되고 예전 비밀번호로는 안 되는지, 회원 전용 보드에 남긴 카드의 작성자명이
따라 바뀌는지, 활동 기록은 그대로인지.
